# Intro Course: CMU 15-445/645 + PostgreSQL Internals

This is a watch-and-read plan. It has no coding projects. You can finish it on an iPad.

Each row is one week. Do the four items in this order:

1. Watch lecture A.
2. Watch lecture B.
3. Read the PostgreSQL Internals chapters. They show the same idea in a system you know.
4. Read the external paper or blog. It gives a second view of the topic.

A week takes about 5-6 hours. Lectures are about 75 minutes each. The book reading is 30-45 minutes. The external read is 30-60 minutes. Split the week over four sessions of about 90 minutes.

## More reads by week

Each week has two or three extra reads: blogs, posts, docs, or talks. Use them after the paper.
Pick the ones that interest you. They are not all required.

1. **Relational model and SQL:** [Modern SQL](https://modern-sql.com/) (browse the feature pages). [PostgreSQL WITH queries](https://www.postgresql.org/docs/current/queries-with.html).
2. **Pages and buffer pools:** [InterDB, ch. 1: Database cluster, databases and tables](https://www.interdb.jp/pg/pgsql01/). [Are You Sure You Want to Use MMAP in Your Database Management System?](https://db.cs.cmu.edu/mmap-cidr2022/)
3. **Log-structured and columnar storage:** [How RocksDB works](https://artem.krylysov.com/blog/2023/04/19/how-rocksdb-works/). [Parquet file format](https://parquet.apache.org/docs/file-format/). [Arrow columnar format](https://arrow.apache.org/docs/format/Columnar.html).
4. **Hash tables and B+trees:** [Anatomy of an SQL Index](https://use-the-index-luke.com/sql/anatomy). [B-trees and database indexes](https://planetscale.com/blog/btrees-and-database-indexes).
5. **Latching:** The lock manager README, the nbtree README, and *The ART of Practical Synchronization* in the table above.
6. **Sorting and joins:** [InterDB, ch. 3: Query processing](https://www.interdb.jp/pg/pgsql03/) (the executor and join sections). [Parallel Grouped Aggregation in DuckDB](https://duckdb.org/2022/03/07/aggregate-hashtable.html).
7. **Query execution:** [How Query Engines Work](https://howqueryengineswork.com/). [PostgreSQL parallel query](https://www.postgresql.org/docs/current/parallel-query.html).
8. **Query optimization:** [How we built a cost-based SQL optimizer](https://www.cockroachlabs.com/blog/building-cost-based-sql-optimizer/). [Using EXPLAIN](https://www.postgresql.org/docs/current/using-explain.html). [Statistics used by the planner](https://www.postgresql.org/docs/current/planner-stats.html).
9. **Concurrency control and 2PL:** [Jepsen consistency map](https://jepsen.io/consistency). [PostgreSQL explicit locking](https://www.postgresql.org/docs/current/explicit-locking.html). [PostgreSQL transaction isolation](https://www.postgresql.org/docs/current/transaction-iso.html).
10. **MVCC:** [The Part of PostgreSQL We Hate the Most](https://www.cs.cmu.edu/~pavlo/blog/2023/04/the-part-of-postgresql-we-hate-the-most.html) (Pavlo). [PostgreSQL transaction isolation](https://www.postgresql.org/docs/current/transaction-iso.html), the snapshot sections.
11. **WAL and recovery:** [InterDB, ch. 9: Write-ahead logging](https://www.interdb.jp/pg/pgsql09/). [PostgreSQL WAL introduction](https://www.postgresql.org/docs/current/wal-intro.html). [pg_walinspect](https://www.postgresql.org/docs/current/pgwalinspect.html).
12. **Distributed databases:** [Amazon Aurora under the hood: quorums and correlated failure](https://aws.amazon.com/blogs/database/amazon-aurora-under-the-hood-quorum-and-correlated-failure/). [Please stop calling databases CP or AP](https://martin.kleppmann.com/2015/05/11/please-stop-calling-databases-cp-or-ap.html). [Raft visualization](https://raft.github.io/).
13. **Survey week:** [Chasing that 32 ms tail latency in ClickHouse](https://clickhouse.com/blog/chasing-32ms-tail-latency-clickhouse). [ClickHouse architecture overview](https://clickhouse.com/docs/academic_overview). [Databases in 2024: A Year in Review](https://www.cs.cmu.edu/~pavlo/blog/2025/01/2024-databases-retrospective.html).
